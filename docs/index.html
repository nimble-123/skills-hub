I · The cabinet

A drawer for every tool.

Claude Code, Cursor, Codex and thirteen more each keep their own folders — some global, some per project, most both. Nothing showed you all of it at once, so the same prompt ended up pasted into three places and drifting apart.

skills-hub reads every one of them in place. The first card in each drawer is its guide: the folders that tool reads, taken from the app’s own registry.

II · The cards

A card for every file.

Four kinds of card, each with its tab cut in its own place and its own colour — the same four colours the app uses.

  • Skill
  • Agent
  • Command
  • Rule

A card is not a copy. It is the file the tool reads, with its path, its description and whether it is switched on.

    Rules of the reading room

    Every action is a real one.

    A checkbox in a manager that never touches the file the tool reads has not disabled anything. So here, it does.

    1. i

      Withdrawing a card moves the file.

      Disabling an item moves it into a .skillmanager-disabled folder beside where it was, and enabling moves it back. The tool genuinely stops seeing it — there is no hidden list of switches.

      It is symlink-aware: a relative link is recomputed for its new depth rather than replaced with an absolute path, so a shared skills folder keeps working after the round trip.

    2. ii

      Your marginalia live in your vault.

      Tags, favourites and collections are kept as one small markdown file per item, almost all frontmatter, in a folder you choose. Put it in an Obsidian vault and they sync with everything else you keep, and stay queryable from Dataview.

      A note is only rewritten when something actually changed, unknown keys and the body survive every rewrite, and a note carrying your own tags is never removed automatically. Your skills are never moved or copied there — only the notes live there.

    3. iii

      Nothing leaves the building.

      No account, no token, no telemetry. It reads the folders on your disk and the history your tools already keep, and it asks the network only when you search a registry, watch a repository or check one for updates.

    Acquisitions

    Find it, install it, and read the diff first.

    Search the skills.sh registry by name, or point it at any repository git can reach. A search result names a repository; watching one clones it, walks it, and lists everything installable in it — so the registry is a way to find repositories, not a second install path that could go stale on its own.

    Anything installed records the commit it came from, so it can be checked for updates, shown as a diff before anything is overwritten, and put back the way it was.

    The stacks

    Three floors. The stairs only go down.

    Built with Tauri and Rust. Dependencies point inwards only, and the rule is enforced by cargo deny, not by discipline.

    1. UI src/

      Knows src/bindings.ts and nothing else.

    2. Adapter src-tauri/

      Knows Tauri and the domain.

    3. Domain crates/core/

      Knows neither. tauri is banned here, $HOME is injected rather than read, and crates/cli drives it from a terminal — the proof it really is decoupled.

    Further reading: ARCHITECTURE.md for the domain model and invariants, and SPEC.md for what it guarantees on disk, each guarantee cited to its test.

    Borrowing

    Take a copy home.

    A universal build — Apple silicon and Intel in one.

    brew install --cask nimble-123/tap/skills-hub

    Builds are not signed yet, so macOS refuses the first launch. Allow it under System Settings → Privacy & Security, where an Open Anyway button now sits — or take the quarantine flag off yourself:

    xattr -dr com.apple.quarantine /Applications/skills-hub.app
    winget install nimble-123.skills-hub

    The winget manifest is in review; until it is merged, take the -setup.exe from the latest release.

    The .deb or the .AppImage from the latest release, which is also where every other installer comes from.

    Latest release
    pnpm install && pnpm tauri build

    Produces the .app and .dmg, or the platform’s equivalent.
