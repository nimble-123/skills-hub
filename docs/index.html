~ $ man skills-hub

Every action is a real one.

NAME

skills-hub — one library over the folders your AI coding tools read, for the four things they keep there:

TYPES

  • skill a folder with a SKILL.md, loaded when it is useful
  • agent a sub-agent definition the tool can hand work to
  • command a slash command or saved prompt
  • rule standing instructions — CLAUDE.md, .mdc, AGENTS.md

DISABLE

Moves the item — a skill’s whole folder, or a lone file — into a .skillmanager-disabled folder beside where it was. Enable moves it back to exactly where it was. The tool genuinely stops seeing it, because it is no longer there. 

mv ~/.agents/skills/review-sql
   ~/.agents/skills/.skillmanager-disabled/review-sql

Symlink-aware: a relative link is recomputed for its new depth and stays relative, so a shared skills folder keeps working after a round trip. Nothing is ever overwritten — a name already taken is refused.

LINK

Puts a global item into a project by symlink, never by copy, in the folder that tool reads for that project. A link cannot drift from its original; removing it takes nothing away.

TAG

Your tags live in your vault: one small markdown note per item, with frontmatter, in a folder you choose. Put it in an Obsidian vault and they sync with everything else and stay queryable from Dataview. A note carrying your own tags is never removed automatically.

~ $ skills-hub update review-sql --show-diff

Find it, install it, read the diff first.

Search the skills.sh registry by name, or point it at any repository git can reach — no account and no token either way. Watching a repository clones it, walks it, and lists everything installable in it.

Anything installed records the commit it came from, so it can be checked for updates, shown as a diff before anything is overwritten, and put back the way it was.

~ $ skills-hub --everything-else

The rest of what it reads.

01 MCP servers

Every MCP server every tool is configured with, global and per project. Read-only: shown, never rewritten.

02 Plugin bundles

From Claude Code and Codex, with their items in the library and the bundle switchable as a whole.

03 Menubar, on macOS

A popover to search the whole library and flip an item on or off. It takes the keyboard without activating the app, so typing in it does not pull you out of your editor. Window and popover switch the same files and tell each other.

    ~ $ cat ARCHITECTURE.md | head

    Built so the boundary is checked, not agreed.

    1. UI src/

      knows the generated bindings, and nothing else

    2. Adapter src-tauri/

      knows Tauri and the domain

    3. Domain crates/core/

      knows neither of the above

    Three layers, dependencies pointing inwards only. The domain crate never imports tauri — cargo deny bans it, so it is enforced rather than promised.

    $HOME is injected rather than read, which is what lets the scanner be tested against temporary directories instead of only the machine it runs on. And a small CLI drives the same domain code from a terminal — that it can exist at all is the proof the domain really is decoupled. 

    $ cargo run -p skills-cli -- scan
$ cargo run -p skills-cli -- usage codex
$ cargo run -p skills-cli -- mcp
